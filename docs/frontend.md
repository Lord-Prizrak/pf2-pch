# Frontend: интерактивный лист персонажа PF2e

## Файлы

| Файл | Назначение |
|---|---|
| `frontend/sheet.html` | **Готовый автономный лист** — один файл со встроенными CSS, JS и JSON-данными персонажей из `sheets/`. Работает без сервера, в т.ч. по `file://`. Не редактируется вручную — собирается из `src/`. |
| `frontend/sheet-empty.html` | То же, но без встроенных персонажей («чистый лист»). Раздаётся сервером как `/sheet-empty.html`. |
| `frontend/src/index.template.html` | HTML-шаблон с плейсхолдерами для сборки |
| `frontend/src/style.css` | Базовые стили: сетка 12 колонок + тема/гамма `default` |
| `frontend/src/theme-official.css` | ТЕМА (только расположение блоков): официальный лист Paizo |
| `frontend/src/theme-sanych.css` | ТЕМА: раскладка листа существующего персонажа (Саныч) |
| `frontend/src/theme-dark.css` | ТЕМА: раскладка «Тёмный VTT» (лента ПЗ сверху) |
| `frontend/src/palette-official.css` | ГАММА (только цвета/шрифты): официальная Paizo (cream) |
| `frontend/src/palette-sanych.css` | ГАММА: ночная пергаментно-зелёная (Саныч) |
| `frontend/src/palette-dark.css` | ГАММА: почти чёрная с янтарём (фанатская VTT) |
| `frontend/src/app.js` | Логика приложения (vanilla JS, без фреймворков и сборки) |
| `frontend/src/data.js` | Заготовки/дефолты канонической схемы |

Сборка одного самодостаточного файла: `python3 tools/build.py`
(подробности — в [tools.md](tools.md)).

## Варианты оформления

В лист встроено 4 темы: **Классический** (default), **Официальный (Paizo)**,
**Лист персонажа (Саныч)** и **Тёмный VTT**. Переключаются селектором в шапке;
выбор сохраняется в localStorage (`pf2e.theme.v1`). Тема, указанная сборщику
через `--theme …`, становится темой по умолчанию для собранного HTML-файла.
Подробнее — в [tools.md](tools.md).

## Возможности листа

### Вкладки
- **Лист** — характеристики (STR/DEX/CON/INT/WIS/CHA с автоподсчётом модификаторов),
  КД/стойкость/щит, спасброски (Fortitude/Reflex/Will), Восприятие, навыки
  (15 навыков PF2e с выбором профичности Ч/У/Э/М/Л), атаки (strikes melee/ranged
  с бросками кубиков), класс DC, заклинания (традиция, атака, DC, слоты по рангам
  perDay/used), HP (current/max/temp, dying/wounded, BT, герой-пойнты),
  устойчивости/невосприимчивости, условия.
- **Инвентарь** — надето / держит / расходники / прочее + монеты (pp/gp/sp/cp), bulk.
- **Био** — происхождение, внешность, история и пр. (`biography.*`).
- **Серверы** — управление подключениями к backend'ам, списки персонажей на серверах, загрузка/выгрузка.
- **Импорт/экспорт** — все способы переноса данных (см. ниже) + ручной JSON-редактор.

### Переключение персонажей
В шапке — выпадающий список всех локальных персонажей, кнопки
**＋** (новый пустой лист) и **🗑** (удалить текущего). Текущий id запоминается
(`localStorage.pf2e.currentId`). Все данные любого персонажа — всегда единый
канонический JSON ([data-format.md](data-format.md)).

### Броски
Кнопки атак бросают d20 + модификатор (крит. 20 → двойной дамаг-куб), кость
урона кликабельна; есть произвольные броски вида `2d6+4`.

## Хранение данных

Все три хранилища используют **один и тот же канонический JSON**:

1. **localStorage браузера** (автосохранение при каждом изменении):
   - `pf2e.characters.v1` — `{ id: sheetJson, ... }` все персонажи;
   - `pf2e.currentId` — текущий персонаж;
   - `pf2e.servers.v1` — список серверов `[{url,name,token,user,jwt}]`.
2. **Встроенный JSON в HTML** — блок между маркерами
  ```html
  <!-- PF2E-SHEET-DATA:START -->
  <script id="pf2e-embedded-data" type="application/json">{ "schema":1, "characters":[ … ] }</script>
  <!-- PF2E-SHEET-DATA:END -->
  ```
  При открытии файлаMerge'ится с localStorage (встроенные данные видны, но не
  затирают локальные правки). Экспорт «Скачать HTML» перезаписывает этот блок
  актуальными данными — получается переносимый файл-«чернильница».
3. **Сервер** — через REST API (см. [server.md](server.md)) с cookie-сессией или API-ключом.

## Импорт / экспорт

Все операции — вкладка «Импорт/экспорт»; данные всегда JSON.

| Направление | Способ | Как |
|---|---|---|
| Экспорт | JSON → буфер обмена | «Скопировать JSON в буфер» (Clipboard API, fallback — выделение текста) |
| Экспорт | JSON → файл | «Скачать JSON-файл» (текущий персонаж) / «Скачать все персонажи (JSON)» (массив) |
| Экспорт | HTML с данными | «Скачать HTML с персонажем» / «Скачать HTML со всеми» — полный лист с обновлённым блоком `PF2E-SHEET-DATA`; открывший файл человек видит персонажей без всякого сервера |
| Экспорт | → сервер | «Загрузить текущего на сервер ⤴» (POST/PUT `/api/characters`) |
| Импорт | буфер → JSON | «Из буфера обмена» (один объект или массив) |
| Импорт | файл → JSON | «Из JSON-файла» (`<input type=file>`, объект/массив) |
| Импорт | HTML-файл листа | «Из HTML-файла листа» — читается блок `PF2E-SHEET-DATA` из выбранного `.html` |
| Импорт | PDF-лист | «Из PDF-листа (fields→JSON)» — парсинг форм-полей заполненного PDF прямо в браузере |
| Импорт | ← сервер | «Обновить текущего с сервера ⤓»; также загрузка из списка на вкладке «Серверы» |
| Импорт/экспорт | вручную | Текстовое поле JSON + «Применить из текстового поля» / «Обновить поле из листа» |

Импортируемый JSON нормализуется (`normalizeSheet`): недостающие поля
дополняются дефолтами схемы, старые версии мигрируют `deepMerge`'ом.

## Работа с серверами (вкладка «Серверы»)

- **Добавить сервер** — по URL (например `http://localhost:8090`); проверяется `/api/health`.
- Для каждого сервера доступны способы авторизации:
  - **Логин/пароль** — кнопки «Войти» и «Регистрация» (`/api/login`, `/api/register`); после входа хранится session-токен ответа (`server.jwt`);
  - **API-ключ** — вставка ключа `pf2e_…` из страницы `/user` сервера (`X-API-Key`).
- Список показывает персонажей **каждого** сервера (`GET /api/characters`): имя, уровень, класс, дата обновления; действия: «Открыть/загрузить» (в локальный лист), «⤴ Выгрузить» и «⤓ Обновить» для текущего, удаление на сервере.
- Несколько серверов одновременно; состояние (url, имя, токен, пользователь) сохраняется в `pf2e.servers.v1`.
- CORS-запросы поддержаны сервером, поэтому лист может работать с `file://` против удалённого API.

## Безопасность и ограничения

- Клиентское приложение без аудита; всё редактируется локально — серверная
  валидация ограничена схемой JSON (см. [server.md](server.md)).
- Токены/API-ключи хранятся в localStorage браузера.
